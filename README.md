# BookBook marketing site

Public marketing site for **BookBook** (working name, D-22): a phone-first homepage, catalog and WhatsApp ordering tool for Indonesian UMKM.
Messaging follows D-46: **“Halaman bisnismu, cukup satu link.”** The homepage leads; the catalog and WhatsApp orders are the supporting line and the Pro pitch.

- Static HTML, CSS and JavaScript, generated by a zero-dependency Node script (`scripts/build.mjs`, Node 18+).
- Interface in Bahasa Indonesia only (D-17, NFR-13), mobile-first from 360 px, tested at 360, 768, 1000, 1280 and 1440 px.
- No third-party requests by default: the font (Plus Jakarta Sans, OFL) is self-hosted, and PostHog loads only when a key is set.
- Lighthouse (mobile, simulated 4G): 100 performance, accessibility, best practices and SEO on the home page; LCP about 1.7 s.

These paths use the reserved slugs from technical/301 §3 (`pricing`, `terms`, `privacy`, `help`). If you add another top-level page, add its path to the product's reserved-slug list too, because merchant pages live at `/[slug]` on the same domain.

## Configuration: `site.config.mjs`

Every undecided or phase-dependent value lives in this one file. Edit it and rebuild.

| Key | What it controls | Status in the documents |
| --- | --- | --- |
| `brand`, `domain` | Name everywhere; example links such as `bookbook.id/kueburina` | Q-04, due before beta (15 Feb 2027) |
| `siteUrl`, `basePath` | Canonical URLs, Open Graph, sitemap | `https://tenyom.com` (from `CNAME`) |
| `support.whatsapp`, `support.email` | Support links in the footer, help, FAQ, legal pages; the form's WhatsApp recipient | D-24: dedicated WhatsApp Business number |
| `signupUrl`, `loginUrl` | Empty: every “Ganti link bio kamu” button leads to the waitlist form. Set: buttons go to the app's sign-up with `utm_*`, `ref` and `src` attached, and the form section becomes a sign-up call to action | Beta opens 15 Feb 2027 |
| `plans.pro.monthlyPrice` | `null` shows “Segera diumumkan”; an integer shows e.g. `Rp49.000` and the annual price | Q-03: Rp49k vs Rp99k test in S9, decided at Gate 1 (29 Mar 2027) |
| `plans.pro.annualAvailable` | Removes the “Segera hadir” label on the 12-for-10 annual plan | Ships in S14 (P1) |
| `founding.*` | Founding-member offer, countdown and terms. Hidden automatically after `deadline` (checked in the browser before the page paints); `enabled: false` removes it | P-06, Phase 0 only |
| `dates.*` | Concierge window, beta date, Lebaran label | README key dates |
| `legal.operator`, `legal.lastUpdated` | Who runs the service, as named in Terms and Privacy | D-30: individual business in 2027 |
| `analytics.posthogKey` | Loads PostHog on marketing pages only and sends `marketing_page_viewed` (path, `utm_*`, `ref`), `cta_clicked` and form events. The privacy page switches its wording to disclose it | 206; on from the beta (D-18) |

Plan limits (20 items, 10 links, 8 social icons, 7/90 days of stats) are also in the config so the home page, pricing page and FAQ never disagree.

## How sign-up attribution works

1. A visitor arrives with `?ref=…`, `?utm_source=…` or `?src=…`, for example from the “Dibuat dengan BookBook” badge on a storefront (F-07, F-14).
2. `assets/js/main.js` keeps those values for the browser session.
3. Before the beta they are added to the WhatsApp message the form opens (“Kode: ref=…”), together with the optional “Tahu BookBook dari mana?” answer (F-01-FR9).
4. Once `signupUrl` is set, they are appended to every sign-up link, so each sign-up's source is recorded from day one (106 §5).

## Deploy to GitHub Pages

`.github/workflows/pages.yml` builds the site and deploys `dist/` on every push to `main` (or by hand from the Actions tab).

1. Merge into `main`.
2. In **Settings → Pages → Build and deployment → Source**, choose **GitHub Actions** (deploying straight from a branch no longer works, because the site needs the build step).
3. Keep the custom domain (`CNAME`, `tenyom.com`) in the Pages settings.

## Before going live

1. **Support number.** Set `support.whatsapp`. While it is empty, the form opens WhatsApp's “choose a chat” screen.
2. **Terms and Privacy.** `/terms/` and `/privacy/` are interim summaries of what the documents commit to (110 §3 and §5, F-12). They say so on the page. Replace them with the advisor-reviewed versions before the beta (S7). The privacy page already mentions Supabase in Singapore; update it if Q-05 moves the data to Jakarta.
3. **Brand and domain (Q-04).** Change `brand` and `domain`, then regenerate the social image (below) and replace `assets/img/favicon.svg` if the logo changes.
4. **At beta.** Set `signupUrl` (and `loginUrl`), add the PostHog key, and set `founding.enabled: false` once the offer is over.
5. **After Gate 1.** Set `plans.pro.monthlyPrice`. From S14, set `plans.pro.annualAvailable: true`.

## Content rules (from the requirement documents)

- Only advertise what the documents describe. Features not live at launch carry a “Segera hadir” label: Insights (S15), link scheduling (S16), annual plan (S14), self-serve data export and deletion (S14).
- No invented prices, numbers or testimonials. The numbers in the hero demo are labelled as a simulation.
- Lead with the homepage, keep the catalog and WhatsApp ordering central, and do not position BookBook as “another Linktree” (R16).
- Prices as integers formatted `Rp99.000` (NFR-14). Friendly, informal Indonesian (“kak”, “toko kamu”, NFR-17).
- Colour contrast meets WCAG AA (NFR-28); tap targets are at least 44 px on the site's own controls (NFR-27).


### Template syntax

`{{ value }}` (escaped), `{{{ value }}}` (raw), `{{> partial }}`, `{{#if value}}…{{else}}…{{/if}}`, `{{#unless value}}…{{/unless}}`. Unknown values stop the build with an error, so typos in templates are caught.
